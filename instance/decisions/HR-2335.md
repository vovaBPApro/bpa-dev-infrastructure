## Ruling

1. **The machine runs as root until cutover.** The orchestrator stays on root
   and does not migrate itself to a service user before the move.
2. **Non-root / privilege-separation work is out of scope** until cutover. The
   operator's reading is that this work was started on the orchestrator's own
   initiative and that the system is not set up for it — the phrase is "у тебе
   система не підлаштована".
3. **Cutover means**: move everything to a new server, bring it up there, and
   have it run on V3 with all features.
4. **Reaching V3 quickly is the priority**, on the operator's stated reasoning
   that development gets easier afterwards because of the orchestrator and the
   infrastructure.

## What this supersedes, and what it does not

Existing non-root work is superseded **for scheduling**, not deleted:
`instance/v3-nonroot-lane-model-2026-08-03.md`, the `ag-s4-5-*` branches, and
the parked `V3-1.9-nonroot-lanes-2026-08-03.md` keep their evidence and their
branches. Nothing there is to be reaped as abandoned; it resumes after cutover
if it still earns a slot. Do not spend sprint hours there in the meantime.

This does not relax any Hard Floor. In particular it does not license host-only
mechanisms: running as root is a decision about the privilege model, not about
whether the host is reproducible from git. See
`instance/incidents/2026-08-04-orchestrator-launcher-unstartable-from-git.md`,
which is a live Hard Floor 5 breach and is *more* urgent under this ruling, not
less — cutover is by definition "bring it up on a new server", and that is the
capability currently measured broken.
