## The workboard was corrupted in git and nothing noticed — V3-0.43

`e0cd52b` committed the board with the document header and all of Phase 0 and Phase 1
**duplicated** — 66 spurious lines — and it passed the full landing gate, because no check
reads `instance/workboard.md`. Root cause: the orchestrator's filing script used
`text.replace(anchor, rowText)` with a *string* replacement, and JavaScript expands `$&`,
`` $` `` and `$'` inside one. The row being filed quoted the regex `` `^([0-9]+) pass$` ``
— a `$` immediately followed by a backtick — so `` $` `` pasted in the entire preceding
document. Later insertions used first-match anchors, so subsequent rows went into the
**stale** copy while state updates went into the live one; the two diverged by 19 rows.

Repaired at `5ba72f0` by restoring `c0c0609` and re-applying every intended change. **A
second defect is still live**: 23 of 78 rows have no state cell at all — including V3-0.23,
the row the whole critical path waits on — and 6 more split into extra cells because their
prose contains an unescaped `|`. Fix lane: `ag-s11-3`. A missing state must be re-derived
from landing evidence, never guessed.

When filing rows programmatically, use a **function** replacement and escape `|` inside
cells. Both are now in the repair script's comments.

## Write briefs against `$LANE_REPORT_PATH`, not `<branch>.report.md`

`orchestrator/fleet/launch-lane.sh:77` derives the report path from the **lane name** and
exports it as `LANE_REPORT_PATH`; `gate/lane-exit.sh` is invoked against exactly that
path. Every brief written so far says `<branch>.report.md` instead, so lanes obey the
brief, the guard checks a file nobody wrote, and the lane terminates
`state: failed reason: report-invalid` having done everything right. The orchestrator then
reads the branch-named file by hand and never notices.

This is not cosmetic: **both reviewers of V3-0.16 REJECTed for exactly this** — "the
required coder terminal report `ag-s5-9-r2.report.md` does not exist" — two review rounds
lost to a naming collision. Filed as **V3-0.31**. Until it lands, write
`$LANE_REPORT_PATH` in briefs and expect `state: failed` from lanes launched before this
note.

## Traps that cost time tonight — do not rediscover them

1. **Verify with the runner under test.** Running `meteorite/prove-candidate.sh` from a
   checkout on `main` while testing a SHA whose fix is *in that script* measures nothing.
   This produced two unwarranted doubts about honest lanes.
2. **umask.** Lane sessions run `0022`, the orchestrator shell and the gate `0077`.
   Fixtures that inherit it break for one and not the other. Measure at `0077`.
3. `land_resolve_bun` refuses when `BUN_BIN` is set — `env -u BUN_BIN` for a gate under
   a gate.
4. Never use `land-main` as a working repository; orchestrator commits come from
   `orch-main` (`instance/incidents/2026-08-03-orchestrator-reset-during-landing.md`).
5. A pending review reports `result: clean` + `remaining: Tier-A review pending`, never
   `NO-GO` — `NO-GO` can never land (V3-0.19).
6. Landing now requires `--item-id` registered in `instance/review-items.tsv`.
   **Orchestrator registers items; lanes must not** — a lane that registers its own item
   can mint a fresh identity, which is the evasion the binding prevents.
7. **Never push to `origin/main` while a landing is open**, not even one line of
   bookkeeping. Doing so aborted a landing that had already passed its rebuild proof —
   third instance of the two-writers pattern, recorded in
   `instance/incidents/2026-08-03-orchestrator-reset-during-landing.md`.
8. **Landings take ~10 minutes** (two suites, shell tier, rebuild proof) and are
   serialised. Run them detached; a foreground timeout kill leaves local `main` at the
   merge commit and must be restored to `origin/main` by hand.

## The pattern worth carrying forward

Nearly every defect tonight was **evidence pointed one step away from the property it
claimed**: a lock on a variable rather than the ref created; an arming check on a timer
rather than on whether anything ran; a size bound on a fragment rather than the message
sent; a rebuild verdict read from a file the subject wrote. The reviewers that caught
them did so by *executing* the thing, never by reading it. The closed/moved/open
disposition (landed `6257a32`) exists because of this and is now instruction, not habit.
