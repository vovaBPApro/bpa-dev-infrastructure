# HR-2613 — the resting top-orchestrator model returns to Fable

## Human words (verbatim, do not reword)

> дозволяю повернути фейбл

Asked in reply to the orchestrator's report that `instance/params.yaml` and the binding pin
disagreed, and offering the two ways to resolve it.

## Ruling

**Resting top-orchestrator model is `claude-fable-5`.** This supersedes HR-2315 item 1, which
pinned Opus on 2026-08-04 and said in terms: *"Do not restore Fable (or any other value)
without a newer HR row."* This is that row.

Everything else in the model stack is untouched: HR-709 items 2–4 stand (Codex `gpt-5.6-sol`
as quota-exhaustion fallback only; child/lane agents on Codex; children lean and autonomous),
and HR-1680 stands — **the orchestrator may not change its own model.** This ruling is the
operator's, and the pin remains a value the orchestrator reads rather than one it chooses.

## The drift this ruling closes, which is the reason it exists

The orchestrator found this while answering a question about restarting, not by auditing:

- **HR-2315 (binding) said Opus.**
- **`instance/params.yaml:140` said `claude-fable-5`, citing HR-709** — the ruling HR-2315
  had already superseded.

So the pin and the configuration had contradicted each other for a day, and **any restart in
that window would have come up on Fable against the then-binding ruling, with nothing
noticing.** The config was accidentally already in the state this ruling now makes correct;
that is luck, not compliance, and it is worth recording as such.

This is the same shape as the fleet-cap drift closed earlier today: a decision recorded and
never carried into the mechanism that acts on it. There, `tools/check-fleet-cap.ts` exists to
make the number and the ruling unable to disagree. **No equivalent check exists for the model
pin**, which is why this went unnoticed — filed as `instance/workboard.md` V3-5.23.

## What must change

- `instance/params.yaml` `orchestrator.top_model` keeps `claude-fable-5` but cites **this**
  ruling instead of the superseded HR-709.
- HR-2315 records that its item 1 is superseded here, so a later reader following the chain
  does not stop at Opus.
- A check that the configured model matches the live pin, in the shape of
  `check-fleet-cap.ts`. Until it exists, this pair can drift again the same way.
