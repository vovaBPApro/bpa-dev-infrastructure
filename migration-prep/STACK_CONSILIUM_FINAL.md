## 1. Verdict in one paragraph

All four proposals independently converged on the same core shape — **one React+Vite SPA, a
buildless Bun+Hono backend, build-time package composition instead of iframes, Postgres+Drizzle,
full-environment Playwright on template-cloned databases** — so that shape wins by consensus and
by evidence (every measured legacy pathology traces to Next.js, iframes/proxy, or hand-managed
symlinks; this shape deletes all three as categories). The synthesis takes the **Test & Reliability
Architect's assembly-root composition** repaired per its fatal attack (the assembly becomes a
**versioned meta-repo**, not a synthetic disposable root), the **AI-Tooling Specialist's explicit
route-literal contracts** repaired per its fatal attack (**flat generated clients, no whole-app
type inference**), the **Pragmatic Delivery Engineer's** deletion list and layered gates, and the
**Platform Architect's** per-schema DB ledgers and `defineAgent` SDK ergonomics. Verdaccio and all
registry-based composition are **rejected** (two-commit dance, mutable dist-tag ambient state,
registry SPOF). Every fatal flaw raised is resolved or explicitly accepted in §9.

## 3. Composition without iframes

### 3.1 The seam: `defineAgent` SDK
The framework repo publishes `@bpa/framework-sdk`: `defineAgent({ id, accent, ui, server, contracts, migrationsDir })`
where `ui` = a factory returning a TanStack route subtree + menu entries + dashboard panels + chat-tool
renderers, and `server` = a Hono sub-app + worker definitions + Drizzle migration set. This is the typed
successor to the never-imported `agent-surface-contract` — except it is the ONLY mount path, so it cannot
be bypassed. The shell's `agents.ts` is the whole registration surface:
`export const agents = [billAgent, milaAgent]` — zero per-agent allowlists, env URLs, or path maps in
framework code.

### 3.2 The mechanism: versioned assembly meta-repo (`bpa-product`)
A fourth, tiny repo — the composition root — **committed to git** (this resolves the "unversioned
lockfile" fatal, §9-B/G):
- `product.lock`: framework SHA + per-agent SHA (the pin-set that IS the product; reviewed, history'd, bisectable);
- the workspace root `package.json` + the **single committed Bun lockfile** (the resolved graph is reproducible from meta-repo SHA);
- stand recipes, the composed Playwright gate config, the toolchain-drift CI check.

`assemble.sh` checks the pinned SHAs out side-by-side under `repos/` (gitignored; local `git clone --reference`
makes this seconds), runs one `bun install` against the committed lockfile, and the result is ONE Bun
workspace: one React tree, one router (composed at assembly, so TanStack's `Register` sees the full tree —
resolving the cross-package typed-routes fatal, §9-F), one Tailwind scan, one origin, one auth context.
**No iframes, no postMessage, no proxy, no HTML rewriting, no Verdaccio, no symlinks — ever.**

### 3.3 Lane workflow (resolves the "two-repo harness mismatch reborn" fatal, §9-B)
- Every coder lane materializes a **per-lane assembly** from `product.lock` (shared warm git+bun caches; target <60s).
  Lanes always typecheck and run Playwright **inside the assembly** — agents never typecheck in isolation,
  so "green in agent repo, red at compose" cannot happen for the pinned pair.
- The lane commits to exactly ONE underlying repo (guard script refuses multi-repo dirty state and refuses
  edits under `repos/` of any repo not assigned to the lane).
- Landing an agent change = agent-repo merge + a `product.lock` bump PR in the meta-repo, where the composed
  `tsc -b` + gate run. Lock bumps are one-line, machine-made, conflict-trivial (last-writer re-runs gate).
- **Cross-repo contract changes**: contract-additive first when feasible (dual-shape window); when not, one
  coordinated meta-repo bump PR pins both new SHAs — that PR is the atomic integration event and its CI is
  the compile gate covering the window. The orchestrator sequences these; expected weekly early, rare later.

### 3.4 Blast-radius bulkheads (shared-process trade, accepted with teeth)
- Workers are separate processes per agent (unchanged).
- Agent server sub-apps mount via lazy import with init-failure containment: a throwing agent module
  disables that agent's routes and flips its health flag; it does not kill boot.
- Agent UI subtrees are route-level lazy chunks behind error boundaries: a broken Mila chunk renders an
  error panel inside the shell chrome; Bill keeps working.

### 3.5 Toolchain contract (resolves §9-D)
`@bpa/toolchain` (framework repo) pins tsc/Vite/Tailwind/ESLint versions + shared tsconfig/eslint bases.
Agent repos MUST extend them; the meta-repo CI fails on version drift. Since the assembly compiles all
source with ONE toolchain, drift is caught at the gate, not in production.

## 4. Contract/typing strategy — the "fixed here, broke there" answer

Four compile-time walls plus two runtime backstops:

1. **One compiler over all composed source** — the meta-repo `tsc -b` is the seam gate; a framework
   contract change that breaks Bill is a red typecheck in ~1–2 min, not a 21-minute stand failure.
2. **Derived, not cast, API types** — contract literals → generated flat clients; `(await res.json()) as X`
   dies; `as any`/`as unknown as` on contract/client files is lint-banned and the gate hard-fails on any
   NEW eslint-disable directive (closing the discipline hole the attacks found).
3. **Typed navigation** — code-based TanStack route trees make a renamed route or changed param a compile
   error product-wide.
4. **One styling system, one scanner, one primitive package** — a class either compiles for everyone or
   no one; assembler-generated `@source` list (a missing agent glob is a gate failure, not silent).

Runtime backstops:
- **Zod validation both directions**: throw in dev/test/stand; in prod, throw on writes, log+alert on reads
  (no silent fail-open on the money path).
- **Invalidation-in-contract**: every mutation contract declares `invalidates: [...queryKeys]`; the client
  wrapper auto-invalidates — the `revalidatePath`→Query-invalidation mapping (136 legacy callsites) becomes
  part of the typed contract instead of per-call discipline.

## 5. Testing architecture + expected cycle times

|---|---|---|

| 2. Unit | Vitest/Node for ported suites; real-PG suites use **template-database cloning** (`CREATE DATABASE … TEMPLATE`, <1s per suite) | 1–2 min |
| 3. Parallel stands: N lanes = N port bands + N template-cloned DBs; 3–4 concurrent stands fit trivially in

Chat determinism via sidecar record/replay, honestly scoped: transcripts are maintenance-heavy; the suite
is small, curated, and quarantined from the hard gate.

## 6. impeccable / design-first fit

React + Tailwind + one token package is impeccable's native habitat. `.impeccable/design.json` + tokens
live in `@bpa/ui` (framework repo); agents consume, never fork. `impeccable detect` runs on every UI diff
(Rule 20). Design-first law: the Ladle gallery + screenshot baselines are the enforcement point — a screen
ships only after its approved design exists and its baseline is committed. Per the binding chat-first
decision, the Bill UI surface to design/rebuild is the pruned minimal core, which keeps the design-approval
loop (the Human) off the critical path of the bulk migration.

## 7. Migration approach (honest scope)

**Phase 0 — spike gate (blocking, ~1–2 weeks of lanes):** build a full-size synthetic assembly (real
package counts, generated contracts at target scale) and measure §11 numbers; run the Bun compat matrix
(argon2/Bun.password, sharp, pdfkit, postgres driver, pg-boss, googleapis streaming). Any red ⇒ the named
fallback activates (Node 22 for that component; React Router 7 for routing) BEFORE bulk work.

**Phase 1 — rails:** meta-repo + assembler + lane workflow; framework skeleton (shell chrome, auth port,
`framework-sdk`, `@bpa/ui`, chat relay); the gate at target times.

**Phase 2 — Bill vertical slice:** login → dashboard → one ledger flow → chat, end-to-end through the real
seam, proving composition + gate timing + OAuth on the new origin.

**Phase 3 — bulk port (the cheap 80%):** `packages/actions` (~96k LOC prod src, zero `next/*` imports —
verified), integrations, queue, workers, db schemas (fresh per-schema baselines), domain/llm/auth cores,
master-orchestrator router/registry, sidecars — re-homing + import paths, Zod stays 3.x, Vitest suites come
along as the day-one regression net.

**Phase 4 — web layer (the honest cost center):** NOT "14 files" — 92 API `route.ts` + ~150 pages of which
~40 are server-data pages needing new contract endpoints + client loaders, plus dozens of server-action
consumers (auth/2FA/reset/invite flows) redesigned as explicit typed POSTs. Mitigations: contract-route
translation is formulaic lane work; UI is rebuilt design-first but **scoped to the chat-first minimal
core**, not all 150 screens; a **middleware behavior inventory** (401-JSON-for-API, public carve-outs,
org-selection redirects, invite tokens, internal HMAC bypass paths) is enumerated into contract tests
BEFORE the legacy middleware is deleted; legacy jsdom web tests are acknowledged dead — replacement
coverage is per-screen Playwright locks written with each rebuilt screen.

**Explicit external lane:** OAuth re-registration (Intuit/Google consoles, redirect URIs, Gmail pub/sub
re-pointing, QBO re-init ~6–8h runbook) — Human-gated secrets territory, scheduled, not priced at zero.

**Delete outright:** agent-proxy.ts (798 lines), KarkasAgentSurface + fragments + postMessage sync,
base-path.ts + basePath class, RSC-204 guards, BillAppPathsManifestPlugin, 9 Playwright configs,
check-shared-symlinks.sh / hydrate-worktree-deps.sh / store-lock.sh and most of the ~80-script stand fleet.

**Order:** Bill before Mila (binding focus rule); Mila's mobile app + booksy-extension stay out-of-scope
for the SPA composition and keep their own runtimes (noted future SDK concern, not a blocker).

## 8. Fatal-flaw ledger (every fatal raised → resolution)

- **A. `hc<AppType>`/tRPC inference cliff (raised 4×):** RESOLVED — no whole-app inference anywhere;
  literal contract objects + flat generated per-domain clients; TS perf gated by Phase-0 numbers.
- **B. Cross-repo lane workflow / unversioned composition root / lockfile home (raised 3×):** RESOLVED —
  committed meta-repo owns lockfile + product.lock; per-lane assemblies; one-repo-commit guard; bump-PR
  protocol (§3.2–3.3).
- **C. Verdaccio two-commit dance + `file:` override footgun + registry SPOF:** RESOLVED by rejection —
  no registry; SHA-pinned source assembly.
- **D. Toolchain-contract gap:** RESOLVED — `@bpa/toolchain` + drift CI (§3.5).
- **E. vitest `vi.mock` ≠ bun test (334k-LOC suite):** RESOLVED — Vitest-on-Node stays; Bun runtime skew
  covered by compat suite + every gate run exercising the real Bun server; Node 22 escape hatch kept warm.
- **F. TanStack cross-package typed route trees:** RESOLVED — routes compose only inside the assembly
  (full tree always present); code-based trees; SDK helper + exemplar; RR7 fallback named and gated.
- **G. Assembly determinism (no committed lockfile):** RESOLVED — same as B.
- **H. Migration understatement (RSC pages, 92 routes, revalidate mapping, OAuth re-registration, Zod 3→4,
  design-first bottleneck):** ACCEPTED AND RE-BUDGETED (§7): Zod stays 3.25; invalidation-in-contract;
  middleware inventory; OAuth lane; chat-first UI scope cap.

## 9. Known risks (accepted, with mitigations)

1. **Bun as prod runtime for a finance core** — single-vendor, fast-moving. Mitigation: pinned version,
   web-standard Hono code, weekly Node-boot CI, per-component Node fallback, compat suite. Residual risk accepted.
2. **Lockstep versions as agents multiply** — one React/Router/Tailwind for all agents forever. Mitigation:
   toolchain package makes bumps one-place; upgrade = one meta-repo bump PR + gate; accepted as the price of
   compile-time composition (runtime skew was strictly worse).
3. **Shared-process blast radius** — mitigated by §3.4 bulkheads + separate workers; accepted (legacy
   "isolation" demonstrably never isolated).
4. **Dev(Vite)/prod(build) divergence** — LANE vs GATE modes differ. Mitigation: gate always runs the prod
   build; visual baselines captured only in GATE mode; SSE tested in both.
5. **Screenshot-gate flake / rubber-stamping** — pinned render container + reviewed-baseline protocol; accepted.
6. **Meta-repo bump serialization at high lane counts** — machine-made one-line bumps + batched gating
   (≤3 disjoint, per standing practice); watched metric, not a blocker at 2 agents.
7. **TanStack Router v1 youth** — code-based trees are mechanically codemod-able; RR7 exit named.
8. **Unmeasured performance numbers** — every number in §5 is a Phase-0 go/no-go gate (§11), not a promise.

## 10. Phase-0 go/no-go numbers (binding before bulk migration)

- Composed `tsc -b`: cold ≤ 3 min, warm ≤ 15 s; tsserver hover/diagnostics on contract+route files < 2 s.
- `vite build` of full-size composed SPA ≤ 3 min cold on the 64 GB VM.
- GATE cycle (install→typecheck→build→DB→boot→smoke) ≤ 8 min cold / ≤ 3 min warm; LANE boot-to-first-test ≤ 60 s.
- Bun compat matrix green for argon2-equivalent, sharp, pdfkit, postgres driver, pg-boss — else that component runs Node 22.
- Any red ⇒ activate the named fallback and re-run; two reds on the same item ⇒ consilium reconvenes on that item only.

## 11. Підсумок простою мовою (для Вови)

1. Айфрейми викидаємо повністю. Кожен агент (Білл, Міла) — це просто пакет коду,
2. який каркас підключає до себе як звичайний модуль: один сайт, одна адреса, один вхід.
3. Через це зникають цілі класи старих багів: логін у рамці, OAuth, розсинхрон адреси, «полагодив тут — зламалось там».
4. Фронт: React + Vite (без Next.js — саме Next давав повільні збірки і найдивніші баги).
5. Бекенд: Bun — сервер стартує з коду за секунди, взагалі без збірки.
6. Все з'єднано типізованими контрактами: якщо хтось зламав API чи маршрут — код просто не збереться, і це видно одразу, а не на стенді.
7. Повні тести (все зібрано, все запущено, Playwright по-справжньому) лишаються, але цикл — 3–8 хвилин замість 21–68.
8. impeccable і «спочатку дизайн, потім код» вбудовані в процес: одна бібліотека компонентів, скріншотні перевірки вигляду.
9. Велике ядро Білла (бухгалтерська логіка, інтеграції, воркери) переносимо майже без змін — це найдорожча частина, і вона переїжджає дешево.
10. Екрани переробляємо через дизайн, але тільки мінімальний набір — бо курс «чат перший, UI мінімальний».
11. Перед стартом — двотижнева перевірка на швидкість і сумісність з чіткими цифрами: не вклались — вмикаємо запасні варіанти, які вже названі.
12. Репозиторії лишаються окремими (каркас + кожен агент), плюс маленьке «складальне» репо, яке фіксує, які саме версії збираються в один продукт.
