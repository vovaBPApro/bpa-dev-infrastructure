# HR-1720 — Deployment drift deferred to v3

Decision (Vova, Telegram decision `watchdog_fix_2026_08_03`, 2026-08-03 09:46Z):
**`defer_v3`** — of the three offered options (arm the watchdog only, run the full
`bootstrap/install.sh`, or defer everything to v3), he chose to defer.

Context he was given before deciding, and his prior conditional (Telegram 1718):

> вотчдог - якщо це просто то пофікси, якщо щось складне то пофіксимо вже в третій
> версіі інфри

The evidence showed it is not simple: `bootstrap/check-unit-drift.sh` (exit 1) finds
8 canonical system units absent from `/etc/systemd/system/`, and the tracked repair
path `bootstrap/install.sh` runs `systemctl enable --now bpa-orchestrator.service`,
restarting the live orchestrator, plus the full test sweep. So the second half of
his conditional applies.

## What this means operationally

No unit is deployed and nothing is armed on this host. Deliberately accepted, with
the consequences recorded here so they are not rediscovered as a surprise:

1. **There is no unattended orchestrator recovery.** If the orchestrator dies
   tonight, nothing restarts it and nothing escalates to the Human. This is the exact
   mechanism behind the 2026-08-01 incident and the 2026-08-03 overnight silence.
   Until v3, orchestrator liveness depends on the Human noticing.
2. **There is no deployment-drift detection.** `bpa-deploy-drift-guard` is itself one
   of the missing units, so further drift will also go unreported.
3. **There is no meteorite timer and no staleness/db-grants/stand-verifier timer.**

`bootstrap/check-unit-drift.sh` remains the on-demand way to see the gap; it is
fail-closed and can be run by hand at any time.

## Standing obligation this creates for v3

v3 must deploy its own supervision from the repository — including unattended
restart, Human escalation when the fleet is below `fleet.notify_human_below`, and
drift detection that is not itself subject to the drift it detects. The dead
`notify_human_below` knob (`instance/params.yaml:54`, referenced nowhere in code) is
part of that scope, not a separate fix on the current host.
