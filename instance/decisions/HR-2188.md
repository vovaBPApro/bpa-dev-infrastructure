## What it requires

1. **Per provider, per hour**, record consumption and persist it — the operator
   asks for a database precisely so the data outlives any one session and can be
   queried later.
2. **Quota level is the interesting number**; input and output token counts are
   the acceptable fallback he names himself if quota level turns out to be hard to
   obtain.
3. **A page with a graph** he can look at and click through. Not a report he has
   to ask for each time.
4. He would include this in v3's functionality.

## What is already known about the hard part

`V3-3.6` already displays quota, so a source exists for at least one provider —
the implementing lane should start by reading what that does rather than inventing
a second path. Token counts per lane are the cheaper half and are available where
the lane's own transcript is.

Two things make this more than a logging task, and both should be stated in the
design before code is written:

- **Providers differ.** Anthropic, Codex/Spark and Fable do not expose the same
  numbers, and a schema that assumes they do will record misleading zeros. A
  provider with no quota signal must be recorded as *unmeasured*, never as zero —
  Hard Floor 7, an unmeasured subject is never a pass, and a graph is exactly where
  a zero silently reads as "we used nothing".
- **This is state outside git.** It belongs in the V3-2.9 enumeration from the
  day it exists, and in the HR-2171 backup set if it is worth keeping — which the
  operator's "в який день скільки квоти витратилось" implies it is.

## Why it is worth building beyond the operator's stated reason

It makes the model-escalation ladder (HR-2166) decidable. That ladder trades cheap
rounds against expensive ones, and today nobody can say what a round costs on each
tier — the argument for or against running more work on weaker models is currently
made from impressions. Hourly per-provider consumption turns it into arithmetic.

It also gives V3-3.9 (quota exhaustion mid-lane) its detector: a rate is what tells
you exhaustion is coming, and exhaustion mid-flight is a work-loss event once
V3-0.37 is understood.
