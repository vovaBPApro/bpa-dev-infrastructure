## Effect

Confirms and sharpens the layering already written in
`instructions/instruction-layers.md` and the target layout in
`instructions/repo-layout.md` (`repos.framework: planned`,
`repos.per_agent: planned` in `instance/params.yaml`): **no duplication** of
orchestrator/infra rules into product repos. Product repos carry product
instructions only.

The new requirement is the **composition** problem: a spawned agent must receive
(a) enough L1 infra context to know who it is, what is expected of it, and what
ecosystem it operates in, and (b) the product context for the repo it is
actually working on — assembled intelligently rather than pasted or duplicated.

## What already exists in this repo (do not rebuild)

- `tools/instructions/compose.ts` — renders a self-contained mission preamble
  for a role: the role's baseline pack **always in full**, plus `--tags`
  additions, plus open interim directives. Fail-closed: `--tags` can only add,
  never remove; an unknown tag is a hard error; a doc is included only if its
  audience matches the role or `all`.
- `instance/packs.conf` — per-role baselines for coder, reviewer, orchestrator,
  manager.
- `tools/instructions/dispatch-check.ts` — refuses any lane prompt lacking the
  compose marker, so hand-assembled prompts cannot launch.

So side (a) — the infra half — is built and enforced.

## The open gap

`compose.ts` reads only **this** repo's `instructions/`. There is no mechanism
for side (b): pulling a product repo's instructions and merging them with the L1
pack. That half cannot be finished yet because the product repos do not exist
(`framework: planned`, `per_agent: planned`), but the interface should be
designed now so the product repos are born matching it rather than retrofitted.

Design questions to settle with Vova before building:

1. Where does a product repo declare its instruction set — a fixed path
   convention, or a manifest the composer reads?
2. Does the product side get its own packs/tags vocabulary, or reuse
   `instance/tags.conf`?
3. Precedence when both layers speak to the same subject — L1 wins, product
   wins, or is overlap itself an error the checker should refuse?
4. Does the compose marker record both layers' SHAs, so a prompt is traceable to
   an exact infra + product pair?

`state: open` — this row stays open until those are answered and routed.
