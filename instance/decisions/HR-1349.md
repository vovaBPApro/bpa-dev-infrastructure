# HR-1349 — Model switching must be instant (mid-session), like the previous orchestrator

date: 2026-08-02
source: Telegram, message 1349
status: binding

## Human words (verbatim, do not reword)

> ну, якщо шо, це можна змінювати миттєво, і попередня версія оркестратора так могла робити.
>
> тож запиши це в план наступній сесії, будь ласочка.
>
> і я тебе зараз підзапущу.

Context — «це» answers the daemon's `/model` relaunch note (`daemon/model-registry.ts`
`RELAUNCH_NOTE`: «Зміна моделі застосовується НЕ миттєво … діє з наступного
старту оркестратора»), sent to him at 11:52 during the session relaunch. He is
correcting that contract: the previous orchestrator version could switch the
model instantly, without waiting for the next start.

## Ruling

1. **A `/model` switch must take effect immediately in the live session**, not
   only on the next orchestrator start. The relaunch-scoped pin
   (`orchestrator/runtime.env`) stays as the durable record, but the running
   session must also switch.
2. Prior art is mandatory input: find how the previous orchestrator version did
   the instant switch (Claude Code supports an in-session `/model` command; the
   daemon can inject it into the tmux session the same way `/compact` is sent).
   Source inventory before reimplementation, per the repo import rule.
3. Related same-morning requirement, msg 1355: `/screen` output must show the
   active provider/model (he cannot see it today). One lane may cover both
   surfaces, but the rulings are separate rows (1355 stays in the triage
   ledger routed to the workboard).
