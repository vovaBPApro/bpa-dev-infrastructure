## The rules

1. **Parallel fan-out is the default**, not a queue. The orchestrator working
   single-threaded is a violation of `autonomy-and-capacity.md`, not diligence.
2. **Fleet floor is ACTIVE**: `instance/params.yaml: fleet.status: active`,
   floor 6, ceiling 15. It had been sitting at `suspended` as a legacy leftover,
   which the orchestrator treated as licence to work alone.
3. **Below three running lanes → report to the Human unprompted**, saying work
   is thin and more should be queued. Do not wait to be asked.
4. **Report capacity as numbers** ("N lanes running, each doing X"), never as
   prose about intent.
5. **Durable rules go in the REPOSITORY, not agent memory.** `instructions/*.md`
   (loaded every session) and `instance/decisions/HR-*.md` are the homes. His
   reason, and it is correct: anything parked in agent memory is forgotten fast.
   The memory file written during this exchange was deleted; `MEMORY.md` now
   carries a standing do-not-add notice pointing here.

## Why he was right, recorded honestly

Nothing technical was blocking parallelism: 12 cores, 241 GB free, Codex at 92%
unused weekly quota. `autonomy-and-capacity.md` *already* said to keep the fleet
saturated, and the orchestrator did the work inline anyway. The rule existed and
was ignored — which is exactly why enforcement moves from prose to a check.

## Enforcement

`instance/params.yaml: fleet.fleet_idle_check` is set to
`tools/state-contract/check.ts:FLEET-IDLE`. The checker fails when the workboard
has open rows and zero lanes are running, when the system lane count is
unavailable, or when the open-row count cannot be determined. This makes the
fleet-idle path fail closed instead of depending on orchestrator discipline.
