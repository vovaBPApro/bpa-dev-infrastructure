Context — his immediately preceding message he is correcting was the orchestrator reporting the HR-271 record (top on Codex gpt-5.6-sol, Claude reserved entirely) and asking whether to relaunch on Codex or move to Opus.

## Ruling

1. **Resting top-orchestrator model is `claude-fable-5`.** Not Sonnet, not Opus,
   not Codex. This corrects the orchestrator's prior record (HR-269/HR-271),
   which he states was captured wrong.
2. **Codex `gpt-5.6-sol` is a quota-exhaustion fallback only** — used only once
   Anthropic quota runs out, not a resting or default posture.
3. **Child/lane agents run on Codex** (unchanged from HR-269 item 2 / HR-271 —
   this part was already correct and stands).
4. **Children must be lean and sufficiently autonomous** so they do not
   round-trip the top orchestrator (Fable) for routine steps — the explicit
   goal is minimizing Fable quota burn, so child-agent design should favor
   fewer top-orchestrator touches per unit of work, not just provider choice.

## Ground truth at the time of this ruling

`bash orchestrator/launch.sh model` (run before this message arrived) already
reported `claude_model=claude-fable-5` — the `runtime.env` pin agreed with this
ruling. The live session at the time of his message was nonetheless running on
Claude Sonnet, not Fable. That mismatch (pin says Fable, live process was
Sonnet) is a separate, real defect — the restart path that brought this session
up did not honor the pin — tracked on the workboard, not resolved by this row.
