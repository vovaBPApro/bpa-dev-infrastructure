## The question put to the Human

V3-1.9 (non-root lanes) was parked at the HR-1726 round cap. The remaining blocker was
not code: the row cannot finish until a service account exists and its provider
credentials are minted by interactive login, which is secret provisioning and therefore
operator-only (CLAUDE.md rule 14).

Options offered: provision the account now; wait for the host cutover (V3-4.3); or ask
for more detail.

## The Human's answer, verbatim

```
decision:nonroot_provisioning_2026_08_03=provision_now
```

## What was done under this authority

`bootstrap/provision-service-user.sh` from the retained branch `ag-s5-1`, with
`instance/lane-service-user.conf`, executed as root on this host:

```
service user provisioned: bpa
uid=1000(bpa) gid=1000(bpa) groups=1000(bpa)
Linger=yes
drwx------ bpa bpa /home/bpa-shell
drwxr-x--- bpa bpa /home/bpa-shell/bpa-dev-infrastructure
drwxr-x--- bpa bpa /home/bpa-shell/.cache/infra-lanes
```

This matches the v1 line's verified shape (`instance/v3-nonroot-lane-model-2026-08-03.md`):
uid 1000, home `/home/bpa-shell`, linger on so `systemd-run --user` works headless.

Reversible: `loginctl disable-linger bpa && userdel -r bpa`.

## What remains for the Human

Credentials must be minted by interactive login **as that user** — no agent can do it
and none should:

```sh
su - bpa
codex login      # writes ~/.codex/auth.json, mode 0600
claude           # writes ~/.claude/.credentials.json, mode 0600
```

Nothing copies them; the lane runs as the same uid with the same `HOME` and the
providers resolve them directly.
