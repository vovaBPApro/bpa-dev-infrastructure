## Interpretation of record

The empty history of `v3` (`git merge-base main v3` is empty) is an intentional
design choice, not the defect the 2026-08-03 consilium initially reported it as.
v3 is a from-scratch rewrite that is deliberately NOT merged into `main` while it
is being built. The sequence he fixed is: finish on the branch → test → deploy →
move to `main` last.

Consequences for how the orchestrator reports and measures:

- "Integrated into main" is **not** a v3 progress metric. Any report that scores v3
  by its distance from `main` is measuring the wrong thing.
- The v3 acceptance bar is v3's own gate — the 9-assertion Docker meteorite gate in
  `scripts/meteorite.sh` per `reports/v3-plan-2026-08-02.md` — plus the D1–D7 runway.
- `v3` is therefore a protected long-lived ref. It is exempt from lane-branch reaping
  under `instructions/branching-policy.md`, which kills short-lived `ag-` lanes; it is
  neither an `ag-` lane nor short-lived. Do not include it in any reap set.
