# HR-2224 — time budgets are per-subject, with named exceptions, not one global raise

Recorded 2026-08-04 from Telegram 2222 and 2224, in reply to the orchestrator's
refusal of V3-0.23 round 3's cost.

## The ruling

The default budget stays short. A **larger budget is granted by name**, to specific
subjects — the meteorite first, because it brings up a whole environment.

He states the reason for keeping the default short himself: waiting on everything
that might be hung slows the whole fleet, and that cost is real too. So this is not
"raise the limit", it is "the limit is per-subject and the exceptions are
enumerated".

## What the orchestrator added, and the operator did not contradict

Two boundaries, stated when the ruling was acknowledged:

1. **The exception must be tracked in git and named.** If a lane can declare itself
   an exception with a flag, every lane that hits the limit will — and the budget
   stops meaning anything. This is the same shape as V3-0.29's trust root: an
   authority a lane can write is not an authority.
2. **A run that exceeds its own budget is still killed and still reported as
   killed.** Hard Floor 7 — a longer budget changes when the axe falls, never
   whether a truncated run may be reported as green. That property is what V3-0.51
   exists to restore.

## Why this ruling arrived now

V3-0.23 round 3 closed a real defect — its reviewer proved by arithmetic that the
stall watchdog decided later than the runner containing it — and its landing then
aborted at `meteorite rebuild-proof-timeout`, because the end-to-end lock costs
395 s against a 900 s meteorite budget that must also cover an apt install, a clean
clone and two in-container suite runs.

The orchestrator refused the trade on two grounds. The operator overruled the first
and did not address the second, so both are recorded:

- **The meteorite budget is our own constant** — the operator is right that
  refusing work because of a number we chose is the wrong way round.
- **The suite going from 98–155 s to 557 s is a separate, recurring cost**, paid by
  every lane and every landing, and it holds the gate lock longer on every posting.
  That cost is not addressed by a meteorite exception and remains a live
  consideration for the V3-0.23 recut.

## Sequence

1. **V3-0.51 lands** — it removes the 120 s lane-harness kill, after which a long
   run is survivable at all.
2. **Per-subject budgets with named exceptions**, the meteorite first.
3. **V3-0.23 recut**, keeping the watchdog correction and re-deciding the 395 s
   end-to-end lock on its merits rather than against a constant.
