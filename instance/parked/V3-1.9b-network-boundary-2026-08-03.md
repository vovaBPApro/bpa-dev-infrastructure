## The finding the row exists for — still true, still unfixed

Under the `bpa` user manager, the identity lanes actually run as:

```
plain localhost probe:                              exit=0
identical unit + IPAddressDeny=localhost
                + IPAddressAllow=127.0.0.53:        exit=0   ← should be denied
```

`systemd.resource-control(5)` warns `IPAddress*` silently has no effect where
cgroup/eBPF support is unavailable: no error, the unit starts, the confinement does not
exist. **Lane network confinement is absent in production while appearing configured.**

## Round 3's blocker, and why it is the interesting one

`orchestrator/fleet/network-boundary-probe.sh:47-56`. The reviewer ran the production
probe under the **root** user manager twice, at 10s and 15s timeouts:

```
HOME=/root XDG_RUNTIME_DIR=/run/user/0 TMPDIR=/tmp BUN_BIN="$(command -v bun)" \
  LANE_NETWORK_PROBE_TIMEOUT_SECONDS=15 bash orchestrator/fleet/network-boundary-probe.sh
```

Both filtered legs returned **124 (timeout)**, not **28 (denied)**. The 0/28 baseline
that established this whole row — measured earlier the same evening — did not
reproduce.

So the row now has the same disease as V3-0.24: **the measurement disagrees with
itself across runs.** Under a fail-closed contract, 124 is inconclusive and correctly
refuses, so nothing unsafe ships — but the evidence that the mechanism *can* observe a
real denial is gone.

## What the recut must establish, in order

1. **A reproducible baseline.** Until the root manager reliably yields 0/28, no
   classification can be trusted, because the only known-good signal is unstable. Treat
   this as the same investigation as V3-0.24 — both are "the same command gives
   different answers at different times under different load", and they may share a
   cause.
2. Only then: the four outcomes (28 → proceed, 0 → refuse, 124 → refuse, other →
   refuse), each proven red when deliberately broken.
3. The exclusion rule from round 2 stands as a permanent lesson: an exclusion removes a
   case that **cannot run**, and must never end a test before its remaining assertions.

## What is settled and must not be re-litigated

- Refuse-to-launch is the correct mechanism; the kernel cannot be made to enforce this
  under an unprivileged user manager on this host.
- The refusal genuinely fires — executed as `bpa`:
  `IPAddressDeny=localhost is serialized but not enforced by the user manager`.
- Refusal precedes lane artifact creation.
- `instructions/single-service-user.md:16-19` honestly disclaims inter-lane isolation
  and kernel-enforced confinement. Keep that wording.
