## The goal, one sentence

Close Phase 0 so the landing loop is provably self-correcting — a lane cannot finish
without a landable report, and an aborted landing cannot leave state behind.

## End point — conditions, not adjectives

1. **V3-0.3 landed.** An aborted landing leaves the target ref and working tree
   unchanged, proven by a test that fails against today's code.
2. **V3-0.2 landed or honestly PARTIAL.** See the risk below: there is no single lane
   contract on this branch, there are two divergent ones. A truthful PARTIAL naming
   what remains counts as success; a "done" that hides the divergence does not.
3. **V3-1.3 (whisper installer) landed, with its container proof explicitly deferred.**
   The installer and its tests land; "install proven in a clean container" does not,
   because `bootstrap/` does not exist on v3 yet and there is nothing to build a
   container from. Deferring the proof is recorded, not skipped.
4. Every row that reads `done` has a landed SHA in `git log main`.

## Close condition — the ungameable version

Counting rows marked `done` is gameable in exactly the way counting review rounds was.
So the close report is produced by **re-executing each row's acceptance command fresh,
against the exact landed SHA, at report time** — not by trusting the lane's
self-reported exit code:

```sh
git -C /root/bpa-dev-infrastructure log --oneline --since='2026-08-03 13:30' main
git show main:instance/workboard.md | grep -E '^\| V3-0\.[23]|^\| V3-1\.3'
# then, at the landed SHA, for each row that changed state:
env -u BUN_BIN bash gate/<row-test>.sh; echo $?
```

Anything that does not reproduce exit 0 live does not count, whatever the lane claimed.

## Circuit breaker

Added at the adversarial seat's insistence, because nothing currently stops a sprint
from burning quota on stalled review rounds: **if fewer than 2 rows land in any
90-minute window, stop dispatching and report NO-GO with evidence.** The overnight
failure was precisely a loop that looked busy, and no rule existed to stop it.

  composition matters more than the clock: 3 of them were documents and a close-out
  record; only 2 were mechanism work. The remaining rows are Tier A and touch `gate/`
  and `orchestrator/`. Plan at **30–45 minutes per row**, not 5.
- **Tier A review load.** `gate/review-policy.conf` puts `gate/`, `core/`, `daemon/`,
  `bootstrap/` and `tools/instructions/` under mandatory independent review. V3-0.2 and
  V3-0.3 both land in it, each costing a full review cycle, and V3-0.2 is likely to
  draw a round-1 REJECT.
- **No CI.** `.github/` does not exist on v3, so every check is triggered by hand.
- **Phase 1 cannot really start.** `bootstrap/` is absent, so no Phase 1 acceptance
  criterion that requires a container can be executed. V3-1.3 lands its installer and
  defers its container proof; that is the honest ceiling this sprint.
