## 1. Decision

**Winner: MULTI-REPO OPERATOR's skeleton**, with two mandatory grafts:

| From | Grafted idea |
|---|---|
| Multi-Repo Operator (base) | `instructions/` (generic) vs `instance/` split; named context **packs** rendered by tooling; gate-run **checker**; requirements **inbox** fail-closing on unrouted directives; cross-repo id uniqueness; new-repo scaffold; checker-predates-L2 sequencing |

All three proposals independently converged on the same four corrections to the
draft, which are therefore settled beyond argument: (1) the draft's routing rule
lacks an **instance bucket** and demonstrably misroutes `migration-day.md` and
`repo-layout.md`; (2) "orchestrator injects excerpts" is the exact hand-pasting
mechanism that already failed and must be replaced by **compiled delivery**;
(3) one-home and index-completeness are **already violated in the new repo**
(12-of-29 index; `governance.md` `mission/<id>` vs `branching-policy.md`

Human words move to a **provenance ledger** cited by id, which makes L1
literally give-to-friends while keeping Rule-21 sanctity.

The draft's three core ideas are KEPT: three layers, first-yes-decides routing
spine, one-home-reference-never-copy. Everything below hardens them.

## 2. Final Architecture

### 2.1 Same skeleton in every repo (L1 / L2 / L3)

- **`CLAUDE.md`** (root contract, ≤120 lines; `AGENTS.md` symlink; no vendor
  forks). Fixed sections: **Mission** (≤5 lines) · **Routing summary** (3 lines
  + pointer to the full rule in L1 — NOT the full tree; the byte-identical-
  across-repos idea is dropped as an N-repo lockstep trap and a context tax on
  lanes that never route anything) · **Hard Floor** (≤10 imperatives, GENERATED
  from docs carrying `floor: true` frontmatter — the checker fails hand-edits,
  killing the summary-vs-source drift vector) · **Load Map** · **Report
  Contract**.
- **`instructions/`** — generic binding law of that layer. Every file has YAML
  frontmatter: `id` (globally unique), `layer` (L1|L2|L3|L2-parked),
  `status` (binding|informational|archived), `audience`
  (orchestrator|coder|reviewer|manager|all), `tags` (from a CLOSED vocabulary
  file), `summary` (one line), `decision` (HR-ids implemented), `floor`,
  `risk` (high ⇒ forced independent review on any diff), `sunset` (predicate on
  a phase key, e.g. `phase != sole-mission`), `overrides` (explicit or none).
  Docs ≤80 lines. Precedence on conflict: **single order L1 > L2 > L3**; a
  lower layer may narrow only via declared `overrides` (the process-vs-fact
  dual precedence is dropped as unlitigatable).
- **`instructions/README.md`** — GENERATED from frontmatter. Regenerated by the
  serialized landing step (single writer), so parallel lanes never conflict on
  it and the 12-of-29 rot class dies permanently.
- **L1-only: `instance/`** — this installation, explicitly non-portable:
  - `params.yaml` — every instance value as a named parameter (operator
    language, timezone, fleet floor/ceiling, model/vendor map, phase keys).
    Generic rules cite parameters, never numbers/names. Params marked
    `protected: true` (autonomy scope, review tiers, permission gates) inherit
    the review tier of their governing doc; all others are light-tier.
  - `repos.conf` + repo registry (current `repo-layout.md` content),
    host runbooks (`migration-day.md`), `incidents.md`, `operator.md`,
    `phase.md`.
  - `decisions/` — per-entry files `HR-<telegram-msg-id>.md` (msg-id keys kill
    sequential-id collisions and hot-file append conflicts): verbatim Ukrainian
    block (sacred, Rule 21), date, tentative routing, `routes-to: <id>` (id,
    not path — survives moves), state `pending|routed|parked|superseded`.
  - `parked.md` — manifest of L2/L3 content parked in L1 (`lang/*`, design
    docs, STACK_DECISION stack choice). A parked file without a manifest row is
    a red check; L2's registration in `repos.conf` auto-flags the whole list
    for promotion.
- **`tools/instructions/`** (L1, Bun): `index.ts` (generator), `check.ts`
  (checker), `compose.ts` (pack renderer), `scaffold.ts` (new-repo init).

### 2.2 Routing procedure (replaces the draft's 3 questions)

**Step 0 — scope, binding by LOCATION:** binding instruction text may exist
only in root `CLAUDE.md`, `instructions/`, `instance/` (params/registry), or as
an open decisions-ledger row (interim). Journals, `migration-prep/`, subsystem
READMEs, memory, chat, dispatch prompts are non-binding by location and may
only cite ids. Evidence/history gets `status: informational`. The bilingual
binding-verb lint (English MUST/NEVER/ALWAYS + Ukrainian
обов'язково/ніколи/завжди, with a quote-block exemption syntax and a
suppression budget) flags binding prose in non-binding locations.

Split a compound directive into smallest separable statements; for each, first
yes decides:

1. **Instance fact** — operator, host, repo registry, concrete numbers, phase,
   verbatim words, this project's history? → **L1 `instance/`**. Tie-breaker:
   a rule carrying an instance value SPLITS — rule text continues to Q2–Q4,
   value goes to `params.yaml`, always in the same lane/commit.
2. **Survives a stranger's completely different product** (after
   parameterization)? → **L1 `instructions/`**.
3. **Applies to every agent of this product family** — including stack,
   language conventions, design system, framework architecture, integration
   contract? → **L2** (or `layer: L2-parked` in L1 + manifest row while L2 has
   no repo). Stack/coding conventions are L2 **by definition** (resolves the
   `lang/` double-classification; STACK_DECISION was right).
4. Otherwise → **L3**, that one agent's repo. Unsure L2-vs-L3 → **L3**;
   promotion to L2 triggers on the second consuming agent, as one
   move-and-delete commit with a 5-line tombstone (`moved-to: <id>`) for one
   landing cycle.

Updating = the same function: grep the id in the generated federated index →
exactly one home (checker-enforced uniqueness via a committed id registry in
L1; the serialized landing queue removes the cross-repo TOCTOU race). The KEY
TEST is a lookup, recorded once in frontmatter, never re-litigated.

### 2.3 Delivery — compiled, fail-closed, VERIFIED (not hand-pasted)

- `compose.ts` input: role + target repo + mission tags. Output: mission
  preamble with a marker header + manifest (doc ids, content hashes, source
  SHAs `L1@<sha> L2@<sha>`).
- **Baseline pack per role is ALWAYS included in full** — lane contract, report
  shape, regression-lock law, tool permissions, secret-scan, active
  phase-derived rules. Tag selection ADDS docs; it can never remove the floor.
  This is the fail-closed answer to silent tag-deselection.
- **Closed tag vocabulary** (`instance/tags.conf`): an unknown tag in
  frontmatter OR in a dispatch call is a hard refusal. Checker coverage rule:
  every `status: binding` doc must be reachable via the baseline pack or ≥1
  real tag for its audience, or carry `pack: none` + reason — a filed-but-
  never-delivered rule is a red check, not a latent incident.
- **Snapshot materialization**: referenced docs >40 lines are not "MUST Read
  <cross-repo path>" pointers — the composer COPIES pinned-SHA snapshots into
  the lane workspace (`context/` dir, the one sanctioned generated copy). This
  fixes the transport fatal: Codex ephemeral lanes hydrate only their own
  worktree and cannot resolve foreign-repo SHAs or paths.
- **Consumption verification**: the lane's terminal report must echo id + hash
  + first heading line of every manifest doc; the landing gate diffs the echo
  against the compose manifest. Missing/wrong echo = NO-GO at landing.
  "Confirmed the list" theater is replaced by a machine check.
- Dispatcher refuses any lane prompt without the compose marker. **Break-glass**
  exists: `DISPATCH_OVERRIDE=<reason>` is accepted only for lanes repairing the
  compose/check tooling itself and is logged to the ops journal — "fail-closed"
  never becomes "cannot dispatch the fix" (the fleet-blocking-preflight lesson).
- In-flight skew: a law change flagged `breaking: true` makes the landing gate
  refuse lanes whose pack SHA predates it; non-breaking changes let lanes
  finish under old law, auditable via the stamped SHAs.
- Orchestrator loading: a **SessionStart hook** (harness-enforced, not ritual)
  loads `instance/params.yaml` + open ledger rows + `audience: orchestrator`
  binding docs; the checker caps that full-load set's total lines, forcing
  demotion to summary when it grows — "small by construction" becomes a gate.

### 2.4 Capture — mechanical at the SOURCE (the B276 fix)

- **Daemon-side auto-mirror**: the Telegram daemon appends every inbound Human
  message (msg-id, ts, text) to `instance/decisions/inbox.jsonl`
  automatically. Capture no longer depends on orchestrator diligence or on
  surviving until the next session — a directive received 5 minutes before an
  OOM-kill is already on disk.
- Orchestrator triages each raw row: `directive` → create
  `HR-<msgid>.md` (verbatim, tentative routing) | `chatter` → mark
  non-directive. Checker: untriaged raw rows >24h = red; HR rows `pending`
  >72h = red unless `parked: <reason> review-by: <date>`; a parked row past its
  review-by date goes red again — **no green-and-lost-forever loophole**.
- **Interim bindingness** (the hot-directive fix): open HR rows are
  provisionally binding the moment they are captured — the SessionStart hook
  loads them and the composer appends them to every pack as "interim
  directives" until the routed doc lands. Capture-to-effective latency is one
  dispatch, not one landing cycle.
- CI invariant: every HR directive must be referenced by ≥1 `status: binding`
  doc via `decision:`, or be `superseded`/`parked`-with-date. Reconciliation
  sweep: inbound Human msg-ids vs ledger — uncaptured directives are a red
  list, closing the only channel B276-class loss ever used.

### 2.5 Enforcement — the checker exists BEFORE the structure relies on it

- `check.ts` runs (a) in the landing gate of every managed repo (pinned L1
  checker SHA per repo, one-line file, bumped by a scheduled lane — chosen over
  latest-L1 to keep landings reproducible), and (b) as a **pre-push hook
  installed by bootstrap in every managed repo**, so the orchestrator's own
  direct doc pushes hit the same checks — the gate-bypass fatal is closed at
  the git layer, not by policy text.
- Checks: frontmatter schema; id uniqueness (committed registry); generated
  index freshness; generic-purity (token blocklist from `instance/` PLUS a
  Cyrillic/non-ASCII detector, so the blocklist failing open on new names is
  backstopped); parked-manifest consistency; binding-verbs outside binding
  locations; Hard Floor section matches `floor: true` sources; pack coverage;
  ledger aging; dangling `decision:`/`overrides:`/tombstone references
  (cross-tree citations resolve by id through the federated index, and are
  optional-unvalidated for a stranger's fork).
- **Governed harness surfaces**: `~/.claude/rules/*.mdc` (a ~6.5k-token
  always-loaded second home that has ALREADY forked from `instructions/lang/`)
  becomes pointers-only; the checker asserts it. Orchestrator memory is a
  cache: any rule-stating entry needs `home: <id>`; a scheduled cron sweep
  (the mechanism exists in this stack) files violations into the inbox as
  defects — an owner and a trigger, not a "weekly intention".
- Instruction-change review tiers, machine-decided: diff touching a
  `risk: high` doc ⇒ forced independent (cross-vendor when available) review;
  other binding docs ⇒ normal lane review; non-protected params, index
  regeneration, tombstones, typos ⇒ light tier, orchestrator-direct with
  checker run. This keeps ceremony proportional so the process survives busy
  days instead of being bypassed.

Major weaks also absorbed: routing tree lives in ONE L1 doc (pointer elsewhere)
— no N-repo lockstep, no per-lane routing tax; Hard Floor generated — no fifth
copy vector; single precedence order + declared `overrides`; `sunset` fires on

the serialized landing step — no hot-file conflicts; `sources`/`decision`
citations resolve by id and are optional cross-tree — stranger's fork doesn't
go red; pack size asserted by the checker (`--assert-budget`, preamble target
≤300 lines / ~2k tokens inject-full core) so the budget is a gate, not a hope.

Honest residual risks (accepted, monitored): semantic near-duplicates
(reworded forks) remain reviewer judgment aided by the topic-overlap report —
no lint can decide them; the binding-verb lint will be noisy for ~a month
(suppression budget + quote exemption specified up front); reuse-by-a-friend
covers the instruction layer + tools, not the whole control plane's host
wiring — scope that claim explicitly when reporting to the Human.

## 6. Підсумок для власника (українською)

1. Всі правила стоять на трьох полицях: спільні для будь-якого проєкту — в
   інфра-репо; спільні для всіх агентів — у репо фреймворку; особисте кожного
   агента — в його репо.
2. В інфра-репо є окрема тека «про нас»: твої слова дослівно, імена, числа,
   налаштування. Загальні правила пишемо без імен і чисел — тому їх можна
   віддати друзям як є, нічого не вичищаючи.
3. Кожне твоє розпорядження бот сам записує в журнал у момент отримання. Поки
   його не рознесли у правильний файл — система світить червоним. Загубити
   тепер неможливо технічно, а не «якщо не забудемо».
4. «Де оновити інструкцію?» — чотири прості питання або пошук за міткою:
   одна відповідь, одне місце, і перевірка не пропустить ані дубль, ані
   правило не на своїй полиці.
5. Агенту перед роботою потрібні правила збирає програма, а не «хтось
   вставив вручну». У звіті видно, які саме правила він читав і якої версії.
6. Зі старих репо кожне правило або переносимо, або свідомо списуємо із
   записом чому. Застарілі копії у старих репо помирають — джерело тепер одне.
