## Interim binding effect

Until this row is routed into the canonical verification and landing instructions, infrastructure changes must use the repository's highest available verification level. The landing path must not depend on a coder voluntarily naming the relevant test suites. Every tracked applicable suite must be inventoried automatically, and every change must be reverified at the landed integration boundary. A missing, skipped, flaky, timed-out, partial, or unverifiable result is `NO-GO`, never clean.

Test runtime is not authority to omit coverage. Slow suites must be made hermetic, isolated, parallel, or otherwise optimized without weakening the required behavior. Runtime-dependent suites use disposable stands and retain teardown and rollback evidence.

## Required routing and enforcement

1. Route this ruling into `instructions/verification-and-locks.md` without
   duplicating its rule across instruction homes.
2. Make the landing gate derive its test inventory from tracked repository
   files rather than a coder-selected `verify:` list or ignored worktrees.
3. Preserve fail-before evidence for the launcher regression class that the
   prior landing checks omitted.
4. Require independent Tier-A review because the change modifies the evidence
   gate itself.
5. Prove the final mechanism from a clean clone and retain exact pre-merge and
   post-merge verification evidence.
