## The disagreement, and how it was settled

The scoping seat proposed cutting `bootstrap/install.sh` into four rows beginning with
a Docker container harness, on the reasoning that no Phase 1 or Phase 2 acceptance
criterion can execute without a container.

The adversarial seat rejected that as a conflation, and the orchestrator verified its
evidence directly rather than taking either seat's word:

```
git show v2-deprecated:bootstrap/bootstrap.test.sh | grep -n 'exit 0'
61:printf '%s\n' '#!/usr/bin/env bash' 'exit 0' > "$verify_fixture/bin/bun"
62:printf '%s\n' '#!/usr/bin/env bash' 'exit 1' > "$verify_fixture/bin/systemctl"
…stubs for git curl tmux flock findmnt docker codex claude
```

The donor validated `install.sh`'s **logic** with stub binaries in a fixture directory
and no container at all. Container proof was reserved for the things that genuinely
need one — a real model download, a meteorite rehearsal. So "port install.sh" and
"build a container harness" are two different unblocks, and welding them together
would make the first row of the sprint the largest and riskiest thing on the board.

Second verified finding: `main` has **zero** `.github/` files while `v2-deprecated`
carries a working `ci.yml`, `run-suites.sh` and its test. CI existed on the old line
and was never ported. Nothing on v3 verifies anything unless a human or the
orchestrator runs it by hand.

## The review-economy change, adopted

The adversarial seat counted sprint 01's Tier A cost: 11 implementation sessions and 9
review sessions across four rows — **review was 45%**. Seven of those nine rejects
changed the outcome, so the cost is earned, not overhead: the reaper would have deleted
the branch `v3` three times over, and the unit drift checker reported clean while its
own template was missing.

The mechanism adopted is therefore **not** to review less. It is:

1. **At most two Tier A rows per sprint.** Row size, not row count, was the only
   variable that correlated with spawning new defects — nothing over roughly 15
   file-touches came back clean on the first round today.
2. **Every lane brief now carries a self-test list** of the specific failure classes
   reviewers keep finding, to be checked before requesting review: `&&` as the final
   statement of a loop or function under `set -e`; a final line without a trailing
   newline dropped by `while read`; treating an unreadable input as an empty one;
   `chmod 000` being a no-op as root; a checker that enumerates what exists and so
   cannot detect absence.
