# HR-309 — generic, self-hosting, and rebuildable from git alone

Promoted to **Hard Floor 5** via `instructions/reproducible-from-git.md`, and into
the `## Mission` section of root `CLAUDE.md`, at his explicit request that it go
into "the most important instruction".

## Three rulings

1. **GENERIC.** This is not a one-off for the current project. It is a reusable
   simulation of a team of up to ten people, for building any product. Anything
   hard-coding this product, host or operator into the mechanism is a defect —
   `instance/` exists to absorb exactly that.
2. **SELF-HOSTING.** The orchestrator is used to build the orchestrator. Improvements
   compound — and so does drift between the running system and the tracked one.
3. **THE METEORITE TEST.** If the host is destroyed, the repository alone must
   rebuild it, quickly. Every script, instruction, step, unit, config and piece of
   decision logic is committed. Secrets stay out, but are enumerated with their
   location, permissions and verification command — "not in git" must never mean
   "not written down".

## What this immediately exposed, and what was done

The question that produced this ruling («для стартапа онбордингу документація є
якась?») was answered by MEASURING, and the answer was that the documented path
does **not** reproduce the running host:

- `bootstrap/install.sh` renders `systemd --user` units and gates on
  `systemctl --user show-environment`, which **exits 1 on this host** (no user
  bus). The live daemon is a SYSTEM unit at
  `/etc/systemd/system/bpa-telegram-daemon.service`.
- Installer default `INSTALL_ROOT=/home/bpa-dev-infrastructure` vs the actual
  `/root/bpa-dev-infrastructure` running as root.
- **The entire lane fan-out mechanism was not in the repo at all** — the parallel
  fleet was being driven from a temp directory and would have vanished on a
  re-clone. This was the orchestrator's own doing: the mechanism was improvised
  during the work and never landed.
- The fleet-nudge watchdog existed only on this host.
- No enumerated list of host-supplied state.

Fixed in the same commit: the fan-out scripts, the nudge script and its systemd
units are captured under `orchestrator/fleet/` with a README recording the real
launch sequence and the host traps (no user bus; `set -u` + compound `local`;
piping git into `tail` swallowing exit codes). Lane `ag-onboarding-truth` owns
productizing them and reconciling the installer, with a Docker rehearsal as
required evidence.

## The recurring failure this names

Every infrastructure defect found today shares one shape: **a path nobody
re-executed in a clean environment.** The `--user` systemd assumption, the fleet
floor rule that existed but was never enforced, test counts nobody reproduced
(W-16), a dispatch gate that refuses its own packs in a fresh clone. "It worked
where it was written" is the common cause, and the meteorite test is the standing
check against it.
